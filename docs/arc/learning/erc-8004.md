# ERC-8004 Trustless Agents (EIP Notes)

**Status**: Draft
**Last updated**: 2026-08-06

Source: [EIP-8004](https://eips.ethereum.org/EIPS/eip-8004) (Draft). Arc deployment notes: [agentic-economy.md](./agentic-economy.md).

## Scope

Onchain discovery + pluggable trust for agents across orgs. **Payments are orthogonal** (x402 can enrich feedback via `proofOfPayment`).

Three registries (per-chain singletons):

| Registry | Role |
| --- | --- |
| Identity | ERC-721 + URIStorage handle → registration file |
| Reputation | Post/fetch feedback signals |
| Validation | Request/record independent validator checks |

Trust models are tiered/pluggable: reputation, crypto-economic re-execution, zkML, TEE oracles.

## Identity

Global ID:

```text
agentRegistry = {namespace}:{chainId}:{identityRegistry}   # e.g. eip155:5042002:0x8004…
agentId       = ERC-721 tokenId
```

- `agentURI` → registration JSON (`ipfs://`, `https://`, or onchain `data:`)
- Owner = NFT owner; can transfer; operators via ERC-721 patterns
- Reserved `agentWallet` metadata: payment receive address; set only via signed `setAgentWallet` (EIP-712 / ERC-1271); cleared on transfer
- Events: `Transfer`, `Registered`, `MetadataSet`, `URIUpdated`

Registration file highlights: `services` (web, A2A, MCP, ENS, DID, …), `x402Support`, `active`, `registrations[]`, optional `supportedTrust[]`.

## Reputation

```solidity
giveFeedback(agentId, value, valueDecimals, tag1, tag2, endpoint, feedbackURI, feedbackHash)
```

Rules:

- Submitter MUST NOT be agent owner or approved operator
- `value` + `valueDecimals` (0–18) required; other fields optional
- Emits `NewFeedback`; endpoint/URI/hash emitted but not all stored onchain
- Revoke via `revokeFeedback`; third parties can `appendResponse`
- `getSummary` requires non-empty `clientAddresses` filter (Sybil mitigation)

Offchain feedback file MAY include A2A `taskId` / MCP tool / **`proofOfPayment`** (`fromAddress`, `toAddress`, `chainId`, `txHash`) — direct Aefi join key from reputation → payment evidence.

## Validation

```text
owner/operator → validationRequest(validator, agentId, requestURI, requestHash)
validator      → validationResponse(...)  # emits ValidationResponse with uint8 response + URIs/hashes/tag
```

## Aefi mapping

| EIP-8004 | Aefi |
| --- | --- |
| Identity NFT + registration | `agent` + `identity_sources: erc_8004` |
| `agentWallet` | wallet linked to agent (payment identity) |
| `NewFeedback` | provider performance / reputation evidence |
| `proofOfPayment` in feedback file | payment ↔ reputation correlation |
| Validation response | credential / quality evidence — **not** task execution authority |

Still true: identity ≠ mandate ≠ task capability ≠ delivery success.

## Security considerations (EIP)

- Sybil inflation of reputation is expected; mitigate by filtering `clientAddresses` / reviewer reputation
- Onchain pointers/hashes are durable audit trails; offchain URIs need integrity hashes when not content-addressed
- Registration proves URI linkage, **not** that advertised capabilities are safe or real — use reputation + validation + TEE tiers
- Validator incentives/slashing are outside the registry
