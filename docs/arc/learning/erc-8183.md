# ERC-8183 Agentic Commerce (EIP Notes)

**Status**: Draft
**Last updated**: 2026-08-06

Source: [EIP-8183](https://eips.ethereum.org/EIPS/eip-8183) (Draft). Arc tutorial/deployment: [agentic-economy.md](./agentic-economy.md).

## Scope

Minimal job escrow protocol: client funds, provider submits, **evaluator alone** completes (or rejects). Evaluator MAY equal client. Optional hooks extend without changing the kernel. Composes with ERC-8004 via attestation `reason` hashes.

## State machine

| State | Meaning |
| --- | --- |
| Open | Created; budget not set/funded; client may set budget, fund, or reject |
| Funded | Escrow locked; provider may submit; evaluator may reject; expiry → refund |
| Submitted | Deliverable submitted; only evaluator completes/rejects; expiry → refund |
| Completed | Terminal — escrow to provider (− optional platform fee) |
| Rejected | Terminal — escrow refunded to client |
| Expired | Terminal — same refund as Rejected |

Allowed transitions (summary):

```text
Open → Funded | Rejected
Funded → Submitted | Rejected | Expired
Submitted → Completed | Rejected | Expired
```

## Roles

| Role | Powers |
| --- | --- |
| Client | `createJob`, optional `setProvider`, `setBudget`, `fund`, reject only while Open |
| Provider | `setBudget`, `submit(deliverable)`; receives funds on Complete |
| Evaluator | `complete` / `reject` when Submitted; `reject` when Funded |

Provider MAY be `address(0)` at creation; client must `setProvider` before `fund`.

## Core surface

- `createJob(provider, evaluator, expiredAt, description, hook?)`
- `setProvider` / `setBudget` / `fund(jobId, expectedBudget, optParams?)` — EIP uses `expectedBudget` front-run protection
- `submit(jobId, deliverable, optParams?)` — `deliverable` is `bytes32` commitment
- `complete(jobId, reason, optParams?)` / `reject(jobId, reason, optParams?)`
- `claimRefund(jobId)` after `expiredAt` — **not hookable** (liveness escape hatch)

### Canonical events (EIP)

```text
JobCreated / JobFunded / JobSubmitted / JobCompleted / JobRejected / JobExpired
(+ ProviderSet when provider assigned later)
```

Index these for high-confidence job lifecycle evidence (`erc_8183_job_lifecycle`, `escrow_release_after_acceptance`).

## Hooks (optional)

`IACPHook.beforeAction` / `afterAction` around hookable calls. Before-hook can block; after-hook revert rolls back whole tx. Examples in EIP: fund-transfer (bridge/swap capital), bidding.

## Arc reference vs EIP

Arc testnet AgenticCommerce tutorial uses:

- `fund(uint256,bytes)` (optParams) — may differ from EIP’s `expectedBudget` parameter shape
- Status names match EIP six states
- `getJob` does not return deliverable — rely on `JobSubmitted` event

Treat EIP as normative protocol intent; treat Arc ABI as deployment truth for indexing.

## Aefi mapping

| ERC-8183 | Aefi |
| --- | --- |
| Job | `commerce_job` |
| client / provider / evaluator | requester, provider, evaluator parties |
| Funded escrow transfer | payment locked evidence |
| JobSubmitted deliverable | deliverable hash |
| JobCompleted reason | evaluation / acceptance attestation |
| JobRejected / JobExpired | negative outcome + refund |

One job may span multiple task executions offchain; ERC-8183 alone does not model task capability ceilings.
